# Звіт: інкрементний колектор Mastodon

**Джерело.** Mastodon (публічні таймлайни хештегів `python`, `opensource`, `linux` на `mastodon.social`) через офіційний REST API `/api/v1/timelines/tag/:tag`. Обрано за відкритий доступ без обов'язкового ключа та задокументовані заголовки лімітів.

**Що зберігаємо.** Канонічна модель у SQLite: `author` (acct), `url`, `date` (UTC ISO-8601), `text` (HTML → чистий текст), `media` (JSON-список URL), а також `tag`, `source`, `source_id`, `fetched_at`. Реблоги пропускаються, щоб не дублювати чужі пости. Експорт у JSONL: `--export`.

**Інкрементність.** Для кожного хештега два курсори: `newest` (наступний прогін іде з `min_id=newest` вперед) та `oldest` (для `--backfill` з `max_id=oldest` назад). Курсор оновлюється після кожної сторінки, тому обрив посеред прогону нічого не втрачає. Один прогін — невелика партія (`PAGES_PER_RUN × PAGE_LIMIT`).

**Ліміти й як із ними працюємо.** Mastodon повертає `X-RateLimit-Limit/Remaining/Reset` і, при перевищенні, HTTP 429 (за документацією — близько 300 запитів на 5 хвилин для одного IP/токена; точні значення залежать від інстансу, тому клієнт логує їх на кожному запиті й не покладається на припущення).
- Пейсинг: фіксована затримка перед кожним запитом.
- 429: очікування `Retry-After` або до `X-RateLimit-Reset`, плюс jitter, потім повтор; при наявності кількох токенів — перемикання на наступний.
- Проактивно: якщо `Remaining ≤ 1`, чекаємо скидання до того, як отримаємо 429.
- 5xx/мережеві збої: експоненційний backoff (до `MAX_RETRIES`).
- 401/403: помилка конкретного хештега логується, решта продовжує.

**Дедуплікація та ідемпотентність.** `UNIQUE(source, source_id)` і `UNIQUE(url)` + `INSERT OR IGNORE`; повторний прогін без нових постів додає 0 записів (перевірено тестом).

**Результати перевірки.** У мок-тесті: 3 сторінки × 40 = 120 нових; один штучний 429 пережито з очікуванням `Retry-After`; повторний прогін — 0 нових; після появи 30 нових постів дотягнуто рівно 30; backfill додав ще 120; дублів немає.

**Обмеження.** Хештег-таймлайн віддає лише публічні пости й не гарантує повної вибірки (залежить від федерації інстансу). Живі цифри лімітів (фактичні `X-RateLimit-*`, кількість 429) беруться з `collector.log` після реального запуску.
